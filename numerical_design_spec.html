Roguelike ARPG 数值体系架构设计说明书

版本: 1.0 | 状态: Draft

核心理念： 本体系结合了 DOTA 的属性衍生机制（作为基础架构）与 Path of Exile 的伤害乘区机制（作为构建深度），旨在实现“高随机性”与“严谨构建”的平衡。

1. 模块化角色构建 (Modular Composition)

角色不再是单一的数据实体，而是由四个解耦的模块动态组装而成：

[素体模型 Model] + [先天天赋 Talent] + [技能 Skills] + [外部修正 Modifiers] = 最终角色
  • 素体模型 (Model): 决定角色的基础三维 (Str/Agi/Int)、基础攻速、模型体积。例如：兽人素体、精灵素体。
  • 先天天赋 (Innate Talent): 唯一的全局机制，通常包含动态逻辑。例如：狂战血统（血越少攻越高）。
  • 技能 (Skills): 既是主动攻击手段，也是 BD 的组件。包含 Tags（标签）。
  • 外部修正 (Modifiers): 局内肉鸽获取的装备、Buff、诅咒。

2. 属性衍生系统 (Attribute Derivation)

采用三维属性作为数值基座，向下衍生战斗属性。

属性 (Attribute) 衍生规则 (Derivation Rule) 说明
力量 (STR) $$HP_{Max} = STR \times 20 + Base$$ 决定生存上限，部分技能提供物理点伤。
敏捷 (AGI) $$Crit_{Rate} = AGI \times 0.2\%$$ 决定暴击率，部分提供攻速/闪避。
智力 (INT) $$Inc_{Elem} = INT \times 2\%$$ 提供元素伤害加成 (Fire/Cold/Lightning)。

3. 伤害计算管线 (The Damage Pipeline)

伤害计算严格遵循以下 5 个阶段的流水线处理：

阶段 I：基础点伤 (Base Flat Damage)

技能的基础伤害并非定值，而是由武器系数和属性加成动态计算：

$$Base = \frac{(Skill_{Min} + Skill_{Max})}{2} + (Weapon \times Coef_{W}) + (Stat \times Coef_{S})$$

阶段 II：伤害转化 (Conversion)

在应用加成前，改变伤害类型（如物理转火）。这允许伤害享受多种类型的加成。

规则： 转化后的伤害将完全继承新类型的加成规则。转化源的数值被扣除，目标数值增加。

阶段 III：加成计算 (The Buckets)

伤害由三个独立乘区决定：

$$Damage_{Final} = Base \times (1 + \sum Additive) \times \prod Multiplicative$$
  • Additive (Inc): 所有“增加 X% 伤害”的词条相加。来源于属性、天赋、普通装备。
  • Multiplicative (More): 所有“额外造成 X% 伤害”的词条相乘。来源于稀有天赋、诅咒。

阶段 IV：暴击与期望 (Crit Expectation)

最终的 DPS 期望值：

$$DPS = Damage_{Final} \times [1 + Crit_{Rate} \times (Crit_{Dmg} - 1)] \times Atk_{Speed}$$

4. 数据配置规范 (YAML)

所有数值均通过数据驱动，配置结构如下：

skills:
  - id: "skill_smite"
    name: "重击"
    tags: ["attack", "physical"] # 标签决定能吃什么加成
    damage_components:
      - type: "physical"
        min: 100
        max: 120
        scaling_source: "str"    # 伤害挂钩属性
        scaling_coef: 1.5

modifiers:
  - id: "mod_fire_glove"
    name: "炎魔手套"
    conversions:                 # 转化逻辑
      - from: "physical"
        to: "fire"
        ratio: 0.5
    stats:                       # 数值修正
        inc_fire: 0.2            # Additive
        more_damage: 0.1         # Multiplicative

5. 特殊机制说明

  • 动态状态 (Dynamic State): 某些天赋（如狂战士）依赖 Current_HP 等运行时状态，在每一帧计算时动态注入公式。
  • 技能组件化: 技能可以是单纯的 Buff（如光环），也可以是触发器（如暴击释放），通过 Tags 进行交互。
